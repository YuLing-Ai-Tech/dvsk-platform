# DVSK Hybrid v0.3 — 技术栈与实施任务书（待评审）

版本：0.3-draft｜基于架构约束的建议，并未审查现有 HTML PPT 仓库源码。

## 1. 技术选择原则
优先复用现有 HTML PPT 项目的技术和渲染器；下表仅为候选。所有模型能力均以 Adapter 封装，确保可替换；业务渲染和企业数据计算保持确定性。

| 模块 | 初步候选 | 决策因素 |
|---|---|---|
| 本地/工作台 | React + TypeScript（若现有项目已用其他框架则复用） | 现有代码、交互组件和发布方式 |
| 云端语义 API | Python + FastAPI + Pydantic | 模型集成、结构化校验、异步任务 |
| 云模型 | 可插拔多模态推理 Adapter | 图像理解质量、结构化输出、隐私与成本 |
| 检索/词典 | PostgreSQL + pgvector + 文本检索 | 关系、版本、混合检索、权限 |
| 样例储存 | 对象存储 + 授权元数据 | 许可、版本、内容摘要、删除请求 |
| 动态发现 | 搜索 API + 许可范围内的页面访问 | 来源可追溯、服务条款、失败回退 |
| 本地 Gateway | TypeScript/Go/Python 均可；与现有环境一致 | 部署简单、强校验、独立测试 |
| 本地渲染 | 既有 HTML/CSS/SVG PPT 生成器 | 已有能力和兼容约束 |
| 测试 | JSON Schema tests + Playwright + 安全出站测试 | 界面/视觉/契约与数据边界 |

**不在此阶段决定**：大模型训练、微服务拆分数量、K8s 上云集群、独立向量数据库、跨领域插件市场。原则为单体优先（云端模块化单体 + 本地 Gateway/Renderer），必要时再解耦。

## 2. 任务前置关系
`M0 现状审计` → `M1 三契约冻结与网关骨架` → `M2 语义候选/样例` → `M3 可执行布局/本地渲染` → `M4 图片解析/动态词典` → `M5 云地集成/试点`。
安全门禁并非最后补：M1 建立、M2–M5 每阶段回归。M4 可以在 M3 完成后并行拆分，但不得影响核心闭环发布。

## 3. 里程碑与任务
### M0 资产审计与定义冻结（预估 2–4 工作日）
- 查既有 HTML PPT：页面模型、模板库、CSS/动画、导出、审批、测试、许可证、部署方式。
- 列出可复用与必须重构的接口，建立 10 条典型模糊描述 + 10 个合规参考图 + 3 组虚拟企业内容。
- **验收**：明确版本基线、MVP 范围、禁做项；有一份可跑的原有渲染 demo。

### M1 Contract/Gateway 骨架（4–6 工作日）
- 定义 3 个 JSON Schema + OpenAPI；契约 fixture 与错误码。
- 实现本地 egress allowlist、分类规则、入站 template allowlist/版本/签名验证；默认拒绝未知载荷。
- **验收**：至少覆盖正确、错误、越界、注入、敏感出站、断网的用例；网关不能绕开。

### M2 视觉语义交互（5–8 工作日）
- 词典 48 条初始条目入库，但把 `renderable` 限定为首批 20 个已测试布局。
- 建云端 `/semantic/interpret`、样例检索、候选确认、候选来源和不确定性标签。
- UI 展示 2–4 组视觉方案；用户一键选择或组合；必要时提出单个澄清问题。
- **验收**：“花瓣展开、略悬浮”等样本具有可理解且不互相重复的候选；用户确认状态不可伪造。

### M3 Layout→Local Render 核心闭环（7–10 工作日）
- 云端 `design/plan` 输出兼容 3 契约的参数化页面；定义至少 20 个可执行布局与 fallback。
- 本地绑定虚构数据、本地 HTML 渲染；文本溢出和重叠检查，确保不泄漏真实内容。
- **验收**：端到端演示 + 短/中/长虚拟内容三套回归；错误明确提示；无未经批准的代码执行。

### M4 动态词典与图片解构（7–12 工作日）
- 公共/授权参考图解析视觉结构及专业词匹配，区分观察与推断。
- 联网设计发现仅采许可的元信息/链接/获准缩略；同义词、相似项去重；reviewed/published/renderable 分级。
- **验收**：新增候选经过人工或规则门禁评审才发布，能回滚，来源和许可可追溯；不因自动抓取污染正式知识。

### M5 云地试点与产品验收（7–12 工作日）
- 接入目标企业部署形态，运行出站拦截及审计检查，接入真实内部内容前完成权限与安全评审。
- 用 A/B 测试比较无语义层生成流程与 DVSK 流程的满意度、完成时间和返工；收集付费意向与试点反馈。
- **验收**：不存在未经授权出站，流程可追踪、可回滚；产品质量指标形成基线报告，不宣称未经测量的提升。

上述估算均以单个熟悉现有代码的小团队、模型服务可用、页面渲染模块能复用为假设；若当前 HTML PPT 架构不匹配，M0 后重估。建议以关键验收关口而非日期作为放行依据。

## 4. 角色建议（小团队）
- 产品/方案 Owner（用户）：需求边界、审美可接受性、企业试点与最终决策。
- 应用/渲染工程：HTML PPT、交互组件、字体/布局、自动化测试。
- 语义/后端工程：词典、语义 Adapter、API、发现与图像解构。
- 安全/Reviewer（可兼职独立）：出站/入站门禁、隐私数据处理、第三方来源许可、回归审核。
- 不能仅依赖 AI 自测：至少让非开发者参与视觉判断和试用。

## 5. 每次 PR 的完成标准
PR 绑定任务与 Contract 版本；先补 fixture/测试再实现；明确新增许可来源；有失败与回退路径；含审计/安全用例；不包含私有样例；实现功能有截图或可重放录屏；独立 Reviewer 签署后合并。

## 6. 核心风险与止损门槛
1. 云端只见抽象形状导致布局质量低 → M3 用虚拟形状与长文本组合验证；若失败先缩窄场景到卡片/图表模板，不允许上传真实材料补救。
2. 词典越积越乱 → 版本、同义/包含/组合关系、人工审核、已发布模板解耦。
3. 生成观感不佳 → 引入真实设计者判定，避免以模型满意度打分替代人类评价。
4. 内容安全 → 禁云端真实数据推理；出站日志审计、敏感字段对抗用例和默认拒绝。
5. 版权与图片许可 → 仅按授权采集、保留原始来源链接及删除/停止使用机制。
6. 成本与延迟不可控 → 缓存词典/样例、超时和限额、记录每任务推理与检索成本。

## 7. 开发启动顺序（可直接给执行团队）
1. 读 01/02/03 规约，枚举所有 unresolved decisions，不写生成器代码。
2. 对现有仓库进行只读模块审计（不能凭文档假定已有功能）。
3. 建 `contracts/` 三 Schema、golden fixtures 和验证 CI。
4. 建受保护的本地 Gateway，先实现拒绝/错误路径。
5. 做“花瓣式悬浮 5 卡片”端到端纵切 demo，以虚拟数据验证。
6. 通过 M3 Gate 后再扩视觉词典、图片解析、联网发现与自动候选更新。

## 8. 推荐目录（按实际现有仓库适配）
```text
dvsk/
  contracts/              # Schema / fixture / 兼容测试
  cloud/semantic/          # 文本与图片语义映射
  cloud/discovery/         # 搜索、来源、许可、候选入库
  cloud/lexicon/           # 词典、审核、发布、版本
  cloud/planner/           # 可执行设计规约
  local/gateway/           # 出站和入站门禁
  local/content/           # 私有数据处理与绑定
  local/renderer/          # 复用 HTML PPT 引擎
  apps/workbench/          # 用户交互与样例确认
  tests/security/          # 敏感数据边界与入侵测试
  tests/visual/            # 排版/截图/字体/溢出
  docs/                    # ADR / 架构决策 / 合规
```

## 9. 未冻结问题清单
- 现有 PPT 引擎语言/结构和可提取模块；目标部署和操作系统；PDF/PPTX 是否必要；商业参考图片许可策略；内部内容形状能否足够抽象；首批客户更看重静态布局还是动画；样例 UI 工作台如何审批发布。

**推荐决定**：先签署三契约边界，再用最小纵切演示验证云地解耦，最后开展广度功能开发。
